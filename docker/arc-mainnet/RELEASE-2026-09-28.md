## Official RPC and indexing scope

The previous per-block path exceeded public-RPC capacity. The replacement keeps
`https://rpc.mainnet.arc.io`, explicitly selects the stable single-chain omnichain
projector, and pins a Ponder 0.17.8 patch with `PONDER_ARC_RANGE_MODE=true`.

- All `eth_getLogs` calls contain explicit XBID Registry/FeeVault or discovered
  Vault/SideToken addresses. The transport rejects unscoped log calls before sending.
- The worker requests address-filtered log ranges, not every intervening block.
  Registry discovery precedes child queries so same-range creation and trades are retained.
- Each poll reads only the head, previous range boundary and new confirmed boundary;
  matched event blocks may additionally be fetched. The existing 30-block window is retained.
- Empty ranges commit durable checkpoints without synthetic events. A changed confirmed
  boundary raises an integrity error and requires operator recovery; it is not silently skipped.
- Starts are serialized at least 1,000ms apart; throttling applies shared 5–30s backoff.
  Identical concurrent Registry reads are deduplicated; failed calls never become empty logs.
- Ponder realtime live-query subscriptions are not used; the application reads PostgreSQL.

Projection migrations preserved the old schemas by renaming them. No schema or application
data was dropped. Latest pre-switch backup: `/opt/xbid-arc/backups/20260928T155404Z/`.
Readiness and repeated checkpoint/head samples must pass; `/health` alone is insufficient.
